# Sing / Speech-to-Singing — private executable experiment

**Development owner:** Fountain-Coach/sing. **DSP owner:** Fountain-Coach/midi2sampler.
**Acoustic/recognition owner:** Teatro/Ear. **Editorial owner:** Satzfunk/Reframe.

This is a separate, **macOS 14+ offline research package**, not a new
MIDI transport, a streaming speech API server, a publishable voice bank,
a phoneme recognizer, or a replacement for the original SingVoice renderer.

## What has been implemented

- Same four-note, three-syllable, typed `Fountain-Coach/midi2` Universal MIDI Packet score as procedural Sing, including vowel-preserving two-note `la`.
- A 48-kHz mono PCM16 WAV reader that **verifies the entire source file SHA-256** against an explicit private manifest.
- Explicit externally supplied **provisional** onset/vowel boundaries. We do not claim a forced aligner, speech recognizer or verified lyric labels.
- Short locally stable vowel pulse discovery by normalized autocorrelation and an experimental **pitch-synchronous overlap-add** renderer. Grain duration is fixed in *source* time while synthesis pulse spacing follows the target MIDI2 note pitch, approximating formant retention. This is a feasibility signal-processing experiment, not clinical/perceptual proof.
- Original syllable onsets are used once per syllable even when a vowel continues over a melisma. No note-labeled WAV concatenation, CoreMIDI, MIDI1 downgrade or parallel transport.
- Actual `Midi2SamplerDSP` package dependency pinned to commit `64aaed8613a1f8eff0fc8bdb76656688848b0f87`. Its exported `SamplerDSP` helpers and `Window.equalPowerScalar` are compiled and invoked for DC removal, analysis, source-volume calibration and onset/vowel blending. Its excluded Corpus/Persistence/LoopStitcher/Resampler files are NOT misrepresented as shipping APIs.
- Renderer-neutral `RenderedSound` initializer exported by SingVoice, so renderer outputs can share the same verified WAV writer and receipt boundary without copying the voice engine.

## Installed vowel-anchor comparison — private, not an accepted singer

The previous standalone source-only prototype is now integrated as a reversible
experiment in `scripts/vowel_anchor.py`. The local macOS source was tested
against the *unchanged* score and native Swift + midi2sampler rehearsal.
The Python implementation consumes the **same original phrase-score JSON**;
the native Swift rehearsal separately compiles that score into typed MIDI 2.0
Universal MIDI Packets. Python is **not** a new MIDI parser, transport, audio
server or instrument, and it must not be represented as receiving UMP packets.

The original Samantha local control fails its strict, original-pitch-to-note
ratio rather than forcing a damaging transposition. A new, private macOS
`Kathy` speech control (not OpenAI and not approved as a reusable voice)
has a locally stable starting vowel pitch sufficiently close to the written
four notes to allow a source-preserving PSOLA research render. It keeps
original onset samples and preserves either a natural 70ms vowel release
(default, with a disclosed 10ms fade) or the older, mostly silent
`source-gap` release for an explicit negative comparison.

Everything is installed and executable from the existing macOS Python:
no external downloads, pip packages, platform or GitHub CI were added.
The private research WAVs and receipts remain in `/tmp`, not Git.

```sh
python3 scripts/make_macos_say_fixture.py --voice Kathy --prefix /tmp/sing-vocal-Kathy
python3 scripts/vowel_anchor.py \
  --source /tmp/sing-vocal-Kathy.wav \
  --source-manifest /tmp/sing-vocal-Kathy.json \
  --score ../../examples/sustained-melisma.json \
  --release-style natural-vowel \
  --output /tmp/sing-vowel-anchor-kathy-release.wav \
  --receipt /tmp/sing-vowel-anchor-kathy-release.json
python3 -m unittest -q scripts/test_vowel_anchor.py
```

**Real Ear acceptance is mixed and explicitly fails phonetic/vocal goals.**
The natural-vowel variant passes the *actual original Ear browser* acoustic
activity and four-note pitch proxy (442 active windows against >430; 260.9,
333.3, 389.8 and 333.3 Hz) without weakening Ear's threshold. However,
Apple's separate SoundAnalysis sees zero vocal-positive windows out of nine
(versus 2/2 on the spoken input), and independent Apple word recognition
returns an empty transcript. It is still instrument-like rather than
qualified singing. The older silent `source-gap` variant fails the
original Ear active-window threshold (427) and is retained solely as
reproducible negative evidence. Original articulated baseline stays untouched.
See [source-addressed Ear evidence](../../docs/evidence/2026-10-24-vowel-anchor-kathy-ear.md).

## Time-varying vowel spectral experiment (WORLD, private only)

The next source-preserving implementation is in
`scripts/world_vocal_tract.py`, **separate from and reversible against**
the existing Swift + midi2sampler instrument and the previous Python
source-grain comparator. The single canonical score is still used, and
only the sustained-vowel renderer is changed through the optional
`vowel_renderer` research callback in `scripts/vowel_anchor.py`.
The Python reference **does not receive typed UMP** and provides no new
MIDI transport.

It implements two source-matched conditions: **frozen** (same source
spectral envelope every frame) and **evolving** (WORLD's time-varying source
spectral envelope plus aperiodicity). Neither recognizes words or makes a
public voice bank. Original source attacks, declared vowel releases and
all four score pitch targets remain identical across conditions.

The development workflow has installed and verified the exact WORLD
research wheels on the **external DockerDisk**, not on the internal
system drive. The self-contained maintenance installer is
`scripts/setup_world_research.sh`; requirements and Python version are
pinned by hashes in `requirements-world-macos-arm64.txt`. This lane is
excluded from normal Swift package dependencies, GitHub CI and publication.
No external model weights, protected voice samples or generated WAVs are
copied into the owning Git repository.

**Actual Ear result:** both conditions pass the unchanged original
Chrome Ear AudioWorklet's acoustic activity and four-note pitch checks.
Independent Apple word recognition hears **nothing** in the frozen
condition but **"Love me."** in the evolving version. The *spoken*
source itself is **"Love me, love."**, NOT an independently verified
`la mi na` source. Neither WORLD condition passes Apple's separate
voice-event classifier (0/9 vocal-positive windows), nor does Ear
recognize the intended sung phonemes. The complete Ear owned regression
preserves `lexical-gate-blocked`, unqualified all-phone output and
failed held-out non-speech witness. Therefore evolving spectra are an
evidence-supported **research direction**, NOT an accepted singer.
Details: [25 October WORLD / Ear evidence](../../docs/evidence/2026-10-25-world-time-varying-vocal-spectrum-ear.md).

Maintenance reproduction (handled by development, not by the studio author):

```sh
cd ~/Developer/sing
sh Experiments/SpeechToSing/scripts/setup_world_research.sh
WORLD=/Volumes/DockerDisk/fountain-coach/devtools/sing-world-venv/bin/python
"$WORLD" Experiments/SpeechToSing/scripts/world_vocal_tract.py \
  --source /tmp/sing-vocal-Kathy.wav \
  --source-manifest /tmp/sing-vocal-Kathy.json \
  --score examples/sustained-melisma.json \
  --trajectory evolving \
  --output /tmp/sing-world-kathy-evolving.wav \
  --receipt /tmp/sing-world-kathy-evolving.json
```

## Source-blind spoken reference admission (research, blocked)

The preferred next development gate is source quality **before** asking
WORLD to make audible singing. An immutable, source-only and fully private
speech cohort is constructed by
`scripts/make_speech_reference_cohort.py`: five local macOS voice
examples, fixed syllable spellings, explicit source activity requirement,
source WAV and manifest hashes, and a plan frozen before independent
speech recognition. **54** WAV filenames from **60** planned combinations
produce only **eight distinct PCM recordings**: repeated spellings
frequently result in identical audio. Ear is not told source wording
during inference; the Sing evaluator
`scripts/verify_spoken_reference.py` independently binds those results
to the original SHA values and counts an identical audio source once.

An exploratory subsequent macOS pitch-baseline control (reproduced by
`scripts/make_provisional_pitch_source.py`) produces a provisional
Karen spoken source with early vowel F0 around 343 / 358 / 358 Hz,
compatible with all four original score notes under the unchanged
0.67–1.90 pitch-ratio bounds. Apple recognizes **`La, me, na.`**
and regards its source audio as speech. **But this is not independently
annotated phoneme truth.** The local experimental lexical list and
Ear's older canonical lexical aliases differ; Ear correctly blocks
this input. No post-hoc alias change is permitted to make a result
pass.

Actual full Ear-owned source-blind evaluations of the *same new source*
show a frozen WORLD candidate transcribed as **`La me, nah.`**,
and evolving WORLD as **`La, me, no.`**. Both have actual browser
acoustic count 445 and accurate four-note pitch proxies, but neither
passes Ear's complete lexical and phoneme gate, and both fail native
vocal evidence (0/9 and 2/9 vocal windows, respectively). This is
important negative evidence: **source-dependent spectral evolution does
not guarantee preservation of articulated syllables.**

Existing native Swift + midi2sampler rendering stays unchanged; the
source is not admitted for production, reusable voice assets, or public
Satzfunk/First Hearing. No request to the author to install, audit
recordings, or classify them. Full SHA-addressed report:
[25 October spoken-source/Ear gate](../../docs/evidence/2026-10-25-spoken-source-blind-admission-ear.md).

Local maintenance test, not a release procedure:

```sh
cd ~/Developer/sing
python3 Experiments/SpeechToSing/scripts/make_speech_reference_cohort.py
python3 Experiments/SpeechToSing/scripts/make_provisional_pitch_source.py
python3 Experiments/SpeechToSing/scripts/verify_spoken_reference.py
python3 -m unittest discover -s Experiments/SpeechToSing/scripts \
  -p 'test_spoken_reference_gate.py' -q
```

## OpenAI audio source (opt-in, not demonstrated live)

The current OpenAI Realtime API (October 2026) supports `gpt-realtime-2.1-mini`
audio responses using `wss://api.openai.com/v1/realtime?model=...`.
`scripts/capture_openai_realtime.py` contains the real Realtime WebSocket
`session.update`, `response.create`, PCM delta capture and 24→48kHz
conversion path. The adapter is **dry-run validated only**: an API key was not
present in the connected shell, so no OpenAI call or OpenAI speech asset has
been generated or auditioned.

Only to execute a private, billable OpenAI speech capture after credentials,
usage and output-derivation rights have been explicitly authorized:

```sh
# In an authorized local Python environment with 'websockets>=14,<17':
# OPENAI_API_KEY is read from the environment, never written or echoed.
python3 scripts/capture_openai_realtime.py --private-research \
  --voice marin --prefix /tmp/sing-openai-speech
swift run sing-speech-rehearsal ../../examples/sustained-melisma.json \
  /tmp/sing-openai-speech.wav /tmp/sing-openai-speech.json \
  /tmp/sing-openai-hybrid.wav
```

The Realtime model is not a singing instrument, may produce non-identical
pronunciations or extra speech, and must not be trusted as its own phoneme
label source. The derived speech is retained privately for evaluation only.
Redistribution, training/derivation rights, AI-generated disclosure, performer
identity, original provenance and watermark handling require admission before
any permanent reusable voice pack or public release. Prompt-generated GPT-Live
custom voices use a different API and are not implicitly available here.

API references: https://developers.openai.com/api/docs/guides/realtime-conversations
and https://developers.openai.com/api/reference/resources/realtime/client-events

## Acceptance and open limits

- Actual *local synthetic-unit* tests cover deterministic audio, source
  integrity rejection, an unchanged MIDI2 melisma and approximate note pitch.
- Actual *macOS spoken-source* experiment generated 249600 frames at 48kHz
  without publication. **Actual shipped Teatro Ear** independently observed
  the final SHA-verified WAV in Chrome 155 with a parallel diagnostic worklet,
  and measured 260.9 / 333.3 / 387.1 / 333.3 Hz against
  ~261.63 / 329.63 / 392.00 / 329.63 targets. All four final pitches have
  high autocorrelation confidence (0.9970 / 0.9780 / 0.9804 / 0.9751);
  this is **not** recognized syllables, verified formants or realistic singing.
  See [Sing's evidence](../../docs/evidence/2026-10-24-speech-derived-melisma-and-ear.md)
  and the separate Teatro Ear owner's browser test.
- No confirmed listener intelligibility, sustained voice naturalness,
  independently verified onset/vowel labels or real-time safety. Speech source
  is processed offline and all sample-mixing is precomputed.
- Ear's independent phoneme recognizer is still pending:
  https://github.com/Fountain-Coach/teatro.fountain.coach/issues/1
- No generated voice banks committed to Git, no new servers, no automated
  editorial approval or public First Hearing.

Follow-up must qualify acoustic pitch and formant retention with source-blind
Ear evidence and an independent phonetic recognition reference corpus. If the
sample treatment loses voice identity or makes syllables unclear, fail the
candidate and improve resynthesis rather than relabel it as an accepted singer.
